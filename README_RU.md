> Инструмент сбора покрытия кода Java на базе JVM Sandbox - неинвазивный мониторинг покрытия на уровне строк

## Введение

DeepCover - это **неинвазивный агент сбора покрытия кода Java** на базе Alibaba JVM Sandbox. Он собирает данные о выполнении строк кода в реальном времени без изменения исходного кода приложения.

### Основные возможности

- **Неинвазивный сбор** -- На основе технологии улучшения байт-кода JVM Sandbox, без изменения исходного кода
- **Покрытие на уровне строк** -- Точные записи выполнения для каждой строки кода
- **Трассировка HTTP-запросов** -- Автоматическая идентификация и отслеживание HTTP Servlet запросов
- **Высокопроизводительная архитектура** -- Асинхронные очереди + пакетная отправка для минимизации влияния на приложение
- **Гибкая конфигурация** -- Детальный контроль имен классов, методов, частоты выборки с динамической горячей перезагрузкой через центр конфигурации
- **Множественные методы экспорта** -- Поддержка экспорта через HTTP и Kafka
- **Интеграция OpenTelemetry** -- Совместимость со стандартом OpenTelemetry для распределенной трассировки

### Внутренняя архитектура агента

Поток сбора внутри одной JVM:

```
                        ┌─────────────────────────────────────┐
                        │          HTTP-запрос                 │
                        └──────────────┬──────────────────────┘
                                       │
                        ┌──────────────┴──────────────────────┐
                        │       HttpServlet.service()          │
                        │   (Точка инструментирования         │
                        │    байт-кода)                        │
                        └──────────────┬──────────────────────┘
                                       │
 Поток событий:                        │
 ┌─────────────────────────────────────┼──────────────────────────┐
 │                                     │                          │
 │  [before]                                                      │
 │  ├─ Создать CodeEntity, привязать к ProcessTop (ThreadLocal)   │
 │  ├─ Проверка частоты выборки (хеш traceId)                     │
 │  ├─ Фильтрация URL (regex ignoreUrls)                          │
 │  │                                                             │
 │  [beforeLine]  <── срабатывает при каждом вызове метода        │
 │  ├─ Получить CodeEntity из ProcessTop                          │
 │  ├─ Защита NPE: codeEntity==null / isSend==1 / codeInfo==null │
 │  ├─ Построить LineEntity (className, methodName, номер строки) │
 │  │   └─ Автодедупликация номеров строк (LinkedHashSet, O(1))  │
 │  ├─ Проверка порога числа выполнений строки                    │
 │  │   └─ Превышен: метка REFUSE, остановка сбора для метода    │
 │  │                                                             │
 │  [after]                                                       │
 │  ├─ Проверка порога числа собранных узлов                     │
 │  ├─ Метка isSend=1, предотвращение повторной отправки         │
 │  ├─ Постановка в LocalAsyncQueue                              │
 │  └─ finally: очистка ThreadLocal, предотвращение утечек памяти│
 │                                                                │
 └────────────────────────────────────────────────────────────────┘
                                       │
                        ┌──────────────┴──────────────────────┐
                        │        LocalAsyncEngine              │
                        │                                     │
                        │  ┌─────────┐  ┌─────────┐           │
                        │  │ Queue 0 │  │ Queue 1 │  ...       │
                        │  │ (пакеты)│  │         │           │
                        │  └────┬────┘  └────┬────┘           │
                        │       │             │                │
                        │  ┌────┴─────────────┴────┐           │
                        │  │   Поток-потребитель     │           │
                        │  │   Отправка HTTP / Kafka │           │
                        │  └───────────────────────┘           │
                        │                                     │
                        │  Автомат: exceptionOverflow()        │
                        │  └─ Превышение порога -> пауза       │
                        └─────────────────────────────────────┘
```

└────────────────┘                                      │  Сравнение:      │
                                                        │  info.version >  │

## Быстрый старт

### 1. Сборка проекта

```bash
mvn clean package -Dmaven.test.skip=true -Dmaven.javadoc.skip=true
```

После успешной сборки в директории `target/` генерируется `deepcover-agent-1.0-SNAPSHOT-jar-with-dependencies.jar`.

### 2. Настройка параметров JVM

Добавьте в параметры JVM целевого приложения:

```bash
-javaagent:/path/to/sandbox/lib/sandbox-agent.jar \
  -Dapp.name=имя-приложения \
  -Denv=test
```

**Внимание**: При использовании SkyWalking APM размещайте параметры DeepCover **перед** параметрами SkyWalking.

### 3. Развертывание модуля DeepCover

```bash
# Способ 1: Копирование в директорию модулей Sandbox
cp target/deepcover-agent-1.0-SNAPSHOT-jar-with-dependencies.jar \
   /path/to/sandbox/sandbox-module/

# Способ 2: Динамическая загрузка через HTTP Sandbox
curl -X POST \
  "http://sandbox-server:port/sandbox/default/module/http/sandbox-module-mgr/active?ids=deepcover"
```

### 4. Проверка установки

```bash
tail -f ~/sandbox/sandbox.log | grep "code-module"
```

### 5. Запуск тестов

```bash
mvn clean test -Dmaven.javadoc.skip=true
```

41 модульный тест, покрывающий основные утилиты и классы сущностей.

## Конфигурация

### Базовая настройка

Скопируйте шаблон конфигурации:

```bash
cp src/main/resources/deepcover.properties.example src/main/resources/deepcover.properties
```

### Справочник параметров

| Параметр | Описание | По умолчанию/Пример |
|----------|----------|---------------------|
| `serviceName` | Имя приложения | - |
| `env` | Среда: test/pre/pro | - |
| `packageName` | Шаблон пакетов (regex) | `com.myapp.*` |
| `ignoreClasses` | Игнорируемые классы (точка с запятой) | `*.logger;*.frame;` |
| `ignoreUrls` | Игнорируемые URL (точка с запятой) | `/health;/metrics` |
| `ignoreAnnos` | Игнорируемые аннотации | - |
| `sampleRate` | Частота выборки (10000 = 100%) | `10000` |
| `limitCodeMethodSize` | Макс. методов на запрос | `500` |
| `limitCodeMethodLineSize` | Макс. сборов строк на метод | `500` |
| `sendDataCenterType` | Способ отправки: 1=HTTP, 2=Kafka | `1` |
| `dataCenterAddr` | Адрес центра данных (HTTP) | - |
| `KAFKA_BOOTSTRAP_SERVERS` | Адрес кластера Kafka | - |
| `KAFKA_TOPIC` | Топик Kafka | - |
| `exceptionThreshold` | Порог автомата исключений | `10` |
| `exceptionCalcTime` | Окно расчета исключений (мин) | `1` |
| `exceptionPauseTime` | Время паузы автомата (сек) | `5` |

Все параметры поддерживают динамическую горячую перезагрузку через команду `syncConfig` без перезапуска.

### Частота выборки

```
sampleRate=10000   # 100% выборка
sampleRate=5000    # 50% выборка
sampleRate=100     # 1% выборка
```

Частота рассчитывается на основе хеша traceId, обеспечивая согласованные результаты между экземплярами.

## API динамического управления

Управляйте модулем динамически через HTTP-сервис JVM Sandbox:

```bash
# Активировать модуль
curl -X POST "http://sandbox-server:port/sandbox/default/module/http/sandbox-module-mgr/active?ids=deepcover"

# Деактивировать модуль
curl -X POST "http://sandbox-server:port/sandbox/default/module/http/sandbox-module-mgr/unactive?ids=deepcover"

# Выгрузить модуль (полная выгрузка, для повторного сбора нужен перезапуск)
curl -X POST "http://sandbox-server:port/sandbox/default/module/http/deepcover/unloadCodeModule" \
  -d "serviceName=имя-приложения"

# Синхронизировать конфигурацию
curl -X POST "http://sandbox-server:port/sandbox/default/module/http/deepcover/syncConfig" \
  -d "sampleRate=5000&exceptionThreshold=20"
```

## Проектирование производительности

DeepCover минимизирует влияние на производительность приложения через:

- **Асинхронные очереди**: Независимый пул потоков (core=4, max=8, queue=256) с CallerRunsPolicy
- **Пакетная обработка**: Локальная агрегация для пакетной отправки, снижение сетевых затрат
- **Выборка**: Детерминированная выборка на основе traceId
- **Умное ограничение**: Автоматическая остановка сбора строк при достижении порога
- **Автомат**: Автоматическая пауза при превышении порога исключений
- **Кэш regex**: Кэширование результатов компиляции Pattern

## Примечания

1. **Влияние на производительность**: Сбор данных создает нагрузку; настройте соответствующую частоту выборки в продакшене
2. **Совместимость SkyWalking**: Агент DeepCover должен загружаться перед агентом SkyWalking
3. **Использование ресурсов**: Собранные данные потребляют память; настройте `limitCodeMethodSize` по необходимости
4. **Сначала тестируйте**: Тщательно проверьте в тестовой среде перед развертыванием в продакшене
