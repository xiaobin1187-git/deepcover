# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in DeepCover, please report it responsibly.

### Where to Report

Please open a [GitHub Issue](../../issues) and use the title prefix `[SECURITY]` so that maintainers can prioritize it appropriately. For highly sensitive vulnerabilities, you may also contact the project maintainers directly.

### What to Include

When reporting a security vulnerability, please provide:

- A clear description of the vulnerability
- The affected version(s) of DeepCover
- Steps to reproduce the issue
- The potential impact (e.g., data exposure, privilege escalation, denial of service)
- Any possible mitigations or workarounds you have identified

### Response Timeline

We aim to follow this timeline:

| Stage | Expected Response |
|-------|-------------------|
| Acknowledgment | Within 3 business days |
| Initial assessment | Within 7 business days |
| Status update | Every 7 days until resolved |
| Fix or mitigation | Depends on severity and complexity |

### Responsible Disclosure

We ask that you:

- Do not publicly disclose the vulnerability before a fix is available
- Give us reasonable time to investigate and address the issue
- Avoid accessing or modifying data that does not belong to you

We are committed to working with the community to verify and fix potential security issues in a timely manner.
